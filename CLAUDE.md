# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Package manager is **bun** (scripts use `bun run`), Next.js runs with **Turbopack**.

```bash
bun run dev              # dev server (Turbopack)
bun run build            # production build
bun run lint             # eslint
npx tsc --noEmit         # typecheck — run before proposing changes

bun run generate:types   # regenerate src/payload-types.ts after ANY collection change
bun run db:fresh         # payload migrate:fresh — wipes the database
bun run db:seed          # seed categories (src/seed.ts)
bun run db:reset         # db:fresh + db:seed
```

There is no test runner configured in this project.

### Required env vars

`DATABASE_URI` (MongoDB), `PAYLOAD_SECRET`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_ROOT_DOMAIN`.

## Architecture

Multi-tenant marketplace (Gumroad-style): vendors get a subdomain storefront, sell digital products, buyers get a permanent library of purchases. Stack: Next.js 16 App Router + React 19, Payload CMS 3 on MongoDB, tRPC 11 + TanStack Query, Stripe Connect, Tailwind v4 + shadcn/ui.

### Three layers, one Next app

- `src/app/(app)/` — the storefront/frontend
- `src/app/(payload)/` — Payload admin UI + REST/GraphQL, generated by Payload (don't hand-edit)
- `src/app/api/trpc/` and `src/app/api/stripe/webhooks/` — the app's own API routes

### Module pattern (`src/modules/<feature>/`)

Every feature follows the same layout, and this is the convention to extend:

```
server/procedures.ts   # tRPC router for the feature
ui/views/              # page-level components (client, use useSuspenseQuery)
ui/components/         # feature-specific pieces
hooks/ store/          # feature-local state (zustand for cart)
types.ts search-params.ts
```

Routers are composed in `src/trpc/routers/_app.ts`. Modules do not import from each other's `ui/`; share via `src/components/` or `src/lib/`.

### Data fetching contract

Server components **prefetch then hydrate**; client views consume with suspense queries. Follow this exact shape when adding a page:

```tsx
const queryClient = getQueryClient()
void queryClient.prefetchQuery(trpc.x.getOne.queryOptions({ ... }))
return (
  <HydrationBoundary state={dehydrate(queryClient)}>
    <Suspense fallback={<XSkeleton />}><XView /></Suspense>
  </HydrationBoundary>
)
```

URL-driven filters go through **nuqs** loaders (`src/modules/products/search-params.ts`) so the server prefetch and the client hook read the same params.

`src/trpc/init.ts` defines `baseProcedure` (injects a Payload instance as `ctx.payload`) and `protectedProcedure` (adds `ctx.session.user`, throws UNAUTHORIZED). All DB access goes through `ctx.payload`, never a raw Mongo driver.

### Multi-tenancy

`@payloadcms/plugin-multi-tenant` scopes the `products` and `media` collections. Super-admins (`roles` includes `super-admin`, checked via `isSuperAdmin` in `src/lib/access.ts`) bypass tenant scoping.

Routing has two modes, and both must keep working:

- **development** — path-based: `/tenants/[slug]/...`
- **production** — subdomain: `slug.ROOT_DOMAIN`, rewritten to the same path route by `src/middleware.ts`

Always build tenant links with `generateTenantURL()` (`src/lib/utils.ts`) rather than hardcoding either form.

Auth cookies are set in `src/modules/auth/utils.ts` with `sameSite: 'none'` + `domain` so the session is shared across subdomains — that config is currently applied in development too, which breaks local cookies.

### Payments

Stripe **Connect**: each tenant holds a `stripeAccountId` and cannot create products until `stripeDetailsSubmitted` is true (enforced in `Products.access.create`). `checkout.purchase` creates a session **on the connected account** (`{ stripeAccount: tenant.stripeAccountId }`) with `application_fee_amount` derived from `PLATFORM_FEE_PERCENTAGE` in `src/modules/home/constants.ts`.

`src/app/api/stripe/webhooks/route.ts` handles `checkout.session.completed` (creates `orders`) and `account.updated` (flips `stripeDetailsSubmitted`). Product metadata rides through Stripe typed as `ExpandedLineItem` in `src/modules/checkout/types.ts`.

### Collections (`src/collections/`)

`Users` (auth, roles, tenants array), `Tenants`, `Products`, `Categories` (self-nesting via subcategories), `Tags`, `Media`, `Orders`, `Reviews`, `Library`. `Orders` and `Library` are admin-hidden and written only by server code — surface them to users through tRPC, not Payload access rules.

Product visibility flags: `isArchived` (hidden everywhere, `getOne` throws NOT_FOUND) and `isPrivate` (hidden from the public storefront but still reachable on the tenant's own store). New product queries must respect both.

`Products.content` is protected rich text — it may only be returned to a user who owns a matching `orders` record. Public queries use `select: { content: false }`.

## Conventions

- Path aliases: `@/*` → `src/*`, `@payload-config` → `src/payload.config.ts`
- No semicolons, single quotes, JSX attributes use single quotes (match surrounding files)
- After editing a collection, run `bun run generate:types` and import from `@/payload-types`
- shadcn/ui components live in `src/components/ui/` and are generated — prefer composing over editing them
